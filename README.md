# Календарь задач

Веб-приложение: календарь с задачами, которые можно создавать, редактировать, удалять
и назначать ответственным. Без бэкенда и без сборки — чистые HTML/CSS/JS.

Данные хранятся **в общем файле на GitHub**, поэтому календарь один на всех:
владелец создаёт задачи и перемещает карточки между днями, а все остальные
открывают ту же ссылку и только смотрят.

**Онлайн-версия:** https://jennya2981.github.io/arup-task-planner/
(общее хранилище — https://github.com/Jennya2981/arup-calendar-data, файл `calendar.json`)

## Запуск

Откройте `index.html` двойным кликом — этого достаточно.

Если хотите запустить через локальный сервер (например, чтобы проверить импорт/экспорт):

```bash
npx serve .          # или: python -m http.server 8000
```

Затем откройте `http://localhost:8000`.

## Как это работает

| Что | Как |
|---|---|
| **Чтение** | файл `calendar.json` читается через GitHub API — все видят одни и те же задачи |
| **Запись** | только владелец: он вводит ключ доступа в приложение, ключ хранится только в его браузере (`localStorage`, ключ `task-calendar.token`) и в код не попадает |
| **Обновление** | приложение опрашивает хранилище: владелец — каждые 20 секунд, посетители — каждые 90 секунд (ограничение GitHub на число запросов без ключа) |
| **Оффлайн** | последняя полученная версия сохраняется в `localStorage` (`task-calendar.shared-cache`) и показывается, если нет связи |

Права определяются наличием ключа: есть ключ — Администратор, нет — Пользователь.

### Настройка владельца

1. Создать fine-grained токен: https://github.com/settings/personal-access-tokens/new
   - репозиторий — только `Jennya2981/arup-calendar-data`;
   - права — **Contents: Read and write**;
   - срок — любой.
2. Открыть приложение, нажать **«Войти как администратор»** и вставить токен.
3. Готово: изменения сохраняются в общий файл, остальные видят их автоматически.

Токен нельзя забыть в коде или в коммите — приложение его никуда не отправляет,
кроме GitHub API, и хранит только в браузере владельца.

### Настройка общего режима

Файл `js/config.js`:

```js
window.CAL_CONFIG = {
  shared: true,                 // false — автономный режим (данные только в браузере)
  owner: 'Jennya2981',
  repo: 'arup-calendar-data',
  branch: 'main',
  file: 'calendar.json',
  pollMs: 20000
};
```

Если `shared: false`, приложение работает как раньше: данные лежат в `localStorage`,
а вход администратора — по паролю (см. раздел «Роли»).

## Возможности

| Раздел | Что умеет |
|---|---|
| **Виды** | День, Неделя, Месяц, Список — переключение в левой панели |
| **Часовая сетка** | День и неделя — полная сетка 00:00–23:00, как в Google Calendar; задачи с временем раскладываются по «дорожкам» |
| **Перетаскивание** | Перенос задач между днями и часами мышью или пальцем (только для администратора) |
| **Роли** | Администратор — полный доступ; Пользователь — только просмотр (кнопки редактирования скрыты) |
| **Задачи** | Название, описание, дата, время начала/окончания, приоритет, статус, ответственный |
| **Ответственные** | Любой набор людей, свой цвет и инициалы, счётчик задач у каждого |
| **Приоритеты и статусы** | Динамический справочник: добавление, переименование, цвет, удаление (с перевешиванием задач) |
| **Фильтры** | По ответственному (в т.ч. «без ответственного»), по приоритету, по статусу |
| **Поиск** | По названию, описанию и имени ответственного (`/` — фокус в строке) |
| **Статистика** | Всего задач, на сегодня, просрочено, выполнено за месяц |
| **Данные** | Экспорт/импорт JSON, полная очистка, отмена удаления задачи |

Просроченные задачи подсвечиваются красным, выполненные — зачёркнутыми.
Колонки выходных (Сб, Вс) уже, чем остальные дни.

## Роли

По умолчанию приложение открывается в роли **Пользователь** — только просмотр:
все кнопки и действия редактирования скрыты, задачи открываются в режиме просмотра
(поля недоступны, есть подсказка), перетаскивание и создание задач заблокированы.

Права **Администратора** выдаются только владельцу: в карточке пользователя слева
есть ссылка **«Войти как администратор»**. В общем режиме она спрашивает ключ доступа
(проверяется запросом к GitHub). Чтобы вернуться в режим просмотра, администратор
выбирает в переключателе роли **«Пользователь»** — ключ удаляется из браузера.

- **Администратор** — создание/редактирование/удаление задач, управление ответственными и справочниками, импорт/очистка.
- **Пользователь** — только просмотр.

В автономном режиме (`shared: false`) вход администратора — по паролю: в `js/store.js`
лежит только SHA-256 хэш (`ADMIN_PWD_HASH`). Сменить пароль — посчитать новый хэш
и подставить его:

```
node -e "console.log(require('crypto').createHash('sha256').update('НОВЫЙ_ПАРОЛЬ').digest('hex'))"
```

> Ограничение: приложение статическое, без сервера, поэтому режим просмотра —
> это ограничение интерфейса, а не серверная защита. Ключ хранится в браузере
> владельца: того, кто его знает, нельзя отличить от владельца.

## Перетаскивание задач

Доступно только в роли **Администратор** (в роли «Пользователь» чипы нельзя перетаскивать).

| Куда бросили | Что происходит |
|---|---|
| **Ячейка месяца** | меняется только дата, время сохраняется |
| **Часовой слот** (неделя/день) | меняются дата и время начала с шагом 15 минут, длительность сохраняется |
| **Полоса «Весь день»** | меняется дата, время очищается — задача становится безвременной |

Дополнительно:

- при переносе появляется уведомление с кнопкой **«Вернуть»** — откат к прежней дате и времени;
- `Esc` во время переноса отменяет его;
- двойной клик по часовому слоту создаёт задачу на этот час, двойной клик по полосе «Весь день» — задачу без времени;
- у края экрана вид автоматически прокручивается.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `N` | новая задача (только для администратора) |
| `D` / `W` / `M` / `L` | день / неделя / месяц / список |
| `T` | перейти к сегодняшнему дню |
| `←` / `→` | предыдущий / следующий период |
| `/` | поиск |
| `Esc` | закрыть окно |

Раскладка клавиатуры значения не имеет (работает и в русской).

## Структура проекта

```
index.html          разметка: сайдбар, тулбар, модальные окна
css/styles.css      стили, светлая и тёмная тема (по системной настройке)
js/config.js        настройки общего календаря (репозиторий, файл, период опроса)
js/db.js            общий календарь: чтение/запись файла на GitHub, ключ, опрос
js/store.js         состояние, справочники, работа с датами, localStorage, CRUD
js/ui.js            отрисовка сайдбара, месяца, недели, дня и списка, роли
js/modal.js         модальные окна задачи, ответственных, справочников, подтверждения, вход владельца, уведомления
js/dnd.js           перетаскивание задач (Pointer Events): цели, предпросмотр, отмена
js/app.js           инициализация, события, горячие клавиши, синхронизация
```

Модули подключены классическими `<script>` и используют общий объект `window.CAL`,
поэтому приложение работает и по протоколу `file://`.

## Данные

Общий режим: всё лежит в файле `calendar.json` репозитория
`Jennya2981/arup-calendar-data` (схема версии 2: задачи, ответственные, динамические
приоритеты и статусы). Копия последней версии — в `localStorage` браузера.

Автономный режим (`shared: false`): всё хранится в `localStorage` браузера по ключу
`task-calendar.v1`. При первом запуске загружается демонстрационный набор задач —
удалить его можно кнопкой «Очистить всё» в левой панели.

Чтобы перенести данные на другой компьютер: «Экспорт JSON» → файл → «Импорт JSON»
(импорт дополняет текущий список, не создавая дублей по id; справочники и роль
также сохраняются/восстанавливаются).
